NOSF one waiting task per VM (paper rule)

Extract at the root of your existing CBMW repository, preserving directory paths.
Each VM can run one task and hold at most one additional waiting task. The selector will skip VMs with their waiting slot occupied.
The runner keeps EFT priority, paper PCP/feedback, rigid task runtimes, 60-second provisioning, and hourly billing. It uses the same main 300 workflows.
Default outputs now go to outputs/nosf_one_wait_120_middle300 to avoid mixing with the unlimited-queue results.

Examples:
python3 scripts/run_nosf_ohio_middle300.py --scenario arrival15_alpha1.2
python3 scripts/run_nosf_ohio_middle300.py --scenario arrival15_alpha4
python3 scripts/run_nosf_ohio_middle300.py --deadline-factor 1.2 --workers 4
python3 scripts/run_nosf_ohio_middle300.py --deadline-factor 4 --workers 4

Re-run scenarios to measure cost and deadline changes; this patch changes scheduling.
